# Introduction Draft

Large language model (LLM) agents have rapidly evolved from single-turn assistants into systems that can plan, act, and verify over external environments. Among these, web agents have emerged as a particularly important class of agentic systems because a large fraction of digital work is mediated through web interfaces, including search, form filling, content management, software collaboration, and enterprise workflows. Recent work has shown that web agents can operate over realistic browser environments by iteratively perceiving webpage state, reasoning about the next action, and executing clicks, typing, or navigation steps in pursuit of a user-specified goal [1, 2, 3]. In the canonical formulation, web agents follow a perception-planning-execution loop, often augmented with memory, tool use, evaluation, and safety mechanisms [1]. Despite rapid progress, reliable task completion in realistic web settings remains difficult, and performance on benchmark environments continues to lag substantially behind human capability [2, 4].

One important reason is that web environments are not merely large text corpora but dynamic, partially observable, long-horizon decision spaces. A web agent must not only read current page content, but also infer which entities are relevant, which constraints must hold, which page transitions are likely to be useful, and which action sequence will satisfy the task objective. This challenge is especially pronounced for text-centric web agents, which rely primarily on HTML, DOM, and accessibility-tree representations rather than screenshot-based multimodal perception. These agents can access rich structural signals, but they must still convert raw semi-structured observations into coherent plans. Recent analyses suggest that the main bottleneck in web agents may lie less in low-level grounding and more in planning: deciding what should be done next, in what order, and under which constraints [5]. This makes planning, rather than perception alone, a promising intervention point for improving text-centric web agents.

At the same time, knowledge graphs (KGs) provide a complementary representational substrate for organizing relational structure, constraints, and reusable execution knowledge. In contrast to the predominantly parametric knowledge encoded inside LLMs, KGs externalize entities, relations, schema, provenance, and queryable structure in an explicit form [6, 7]. This explicitness has made KGs newly relevant in the LLM era, particularly in systems that require structured retrieval, multi-hop reasoning, controllable updates, and inspectable evidence. Recent work on GraphRAG and KG-based question answering has demonstrated that graph-structured retrieval can outperform plain text retrieval when tasks depend on relational structure rather than isolated passages [8, 9]. However, most of this line of work has focused on answering questions or generating responses. Much less is known about how a site-specific executable KG can support action planning in interactive web environments, where the objective is not only to retrieve information but to decide and execute the next step.

This gap is important because web planning is inherently relational. Solving a realistic task may require understanding which page type a current DOM instance belongs to, which UI elements trigger which action types, which form fields require which constraints, which navigation paths typically reach a target state, and which validation rules or failure patterns have previously arisen on the same site. Existing text-centric web agents often leave this structure implicit in prompt context or episodic summaries. As a result, they must repeatedly rediscover site-specific regularities from raw observations. We argue that, for text-centric web agents, a more suitable intervention is to represent site structure and action-relevant constraints explicitly as a site-specific executable KG, and to use that graph not merely as a retrieval backend, but as a planning substrate for action selection.

In this paper, we study whether natural-language task intent can be translated into an executable graph query over a site-specific KG, and whether the resulting subgraph evidence can improve planning in text-centric web agents. Our focus is deliberately narrow. We do not propose a universal web agent, a multimodal browser agent, or a fully general semantic parsing system for arbitrary SPARQL generation. Instead, we introduce a constrained executable query representation that is tailored to a specific website and its task-relevant action structure. This representation is used to retrieve graph evidence such as candidate entities, navigation relations, constraints, and likely action paths, which are then provided to an otherwise fixed text-centric planner. By keeping the planner and browser executor largely unchanged, we isolate the effect of graph-guided planning from improvements that might arise from unrelated increases in model capacity or orchestration complexity.

Our approach treats the site-specific KG as an external structured memory for acting. The graph contains relatively stable site knowledge, such as page types, UI affordances, navigation relations, and validation rules, as well as dynamic instance-level and episodic knowledge accumulated during task execution. This design allows us to examine two related questions. First, can executable query-guided graph evidence improve verified success rates over text-only planning baselines, especially on relation-heavy and constraint-sensitive tasks? Second, can incremental graph augmentation during a task stream help the agent adapt to a specific site over time, improving later-task performance and enabling recovery on previously failed tasks? The latter question is secondary in this paper, but it is important because practical web agents are often deployed repeatedly on the same site rather than only once in a cold-start setting.

To answer these questions, we evaluate on text-centric settings derived from WebArena-Verified across Shopping, Reddit, and GitLab environments. We compare a base text agent against baselines with episodic memory only, KG retrieval without executable intent translation, a compute-matched no-KG variant, and our full graph-guided planning method, with and without continual KG updates. This design allows us to separate the effects of graph structure, plain memory, and additional deliberation budget. We further analyze executable query rate, entity and schema linking quality, graph evidence utilization, task-type sensitivity, and failure modes such as stale graph edges or incorrect query translation.

This paper makes three contributions. First, we propose an executable intent-to-query planning layer for text-centric web agents, which converts task intent into a constrained graph query and uses the resulting graph evidence to guide action planning. Second, we define a site-specific executable KG for web planning that models page structure, UI affordances, action preconditions, navigation relations, and validation constraints in a form usable for interactive decision making. Third, we introduce an evaluation protocol that measures not only cold-start performance but also continual site adaptation and failed-task replay under incremental graph updates. Together, these contributions position site-specific KGs not as a retrieval-only add-on, but as a practical planning substrate for action-oriented LLM agents in structured web environments.
