# H1: task 309 — single URL 템플릿 단축 (RET)

**Type**: RETRIEVE
**Source**: WebArena-Verified task 309

## Intent
> Get the username(s) of the user(s) with the most commits to the thoughtbot/administrate project

Start URL: `http://localhost:8023`

## Hypothesis
GitLab의 contributor graph 페이지(`/{namespace}/{project}/-/graphs/master`)는 KG의 `project/contributor_graph` 클래스로 매핑되어 있고, URL 템플릿이 directly 알려져 있다. 에이전트는 V1에서 KG 단축 URL을 인용·신뢰해 contributor graph 페이지로 1~2 hop에 도달, 상단 기여자 이름을 추출한다. V0는 프로젝트 페이지 진입 후 사이드바·메뉴를 탐색하여 contributor 페이지를 발견해야 하므로 더 많은 step이 든다.

## Predicted V0
- step 1: explore에서 thoughtbot 검색 또는 dashboard에서 thoughtbot/administrate 직접 클릭.
- step 2~3: 프로젝트 메인 → "Project" 또는 "Repository" 메뉴 탐색.
- step 4~5: Contributors / Graphs 진입.
- step 6 전후: 상단 기여자 식별 → report_success(answer=...).
- 예상 step 수: 5~7

## Predicted V1
- step 1: KG 힌트가 `/thoughtbot/administrate/-/graphs/master`를 단축으로 노출. 에이전트는 thought에 그 URL 또는 contributor 라벨을 인용 후 `goto`.
- step 2: contributor 페이지 도달 → 상단 사용자명 식별 → report_success.
- 예상 step 수: 2~3

## Mechanism invocation signal (V1 log)
- `[KG] inferred target=project/contributor_graph` (또는 동등 클래스명) — 합의 K/K
- agent thought 또는 tool 호출에 `/-/graphs/` 경로 포함
- HAR에 `/thoughtbot/administrate/-/graphs/master` GET 요청

## Falsification criterion
- V1의 step 수가 V0보다 *같거나 많음*, **and**
- V1 thought에 KG가 노출한 contributor 단축 URL/레이블 인용 *없음*

→ 위 두 조건이 모두 성립하면 H1 가설은 본 task에서 refuted.
