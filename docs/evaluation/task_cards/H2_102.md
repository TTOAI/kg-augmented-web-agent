# H2: task 102 — 다중 hop + filter category 노출 (NAV)

**Type**: NAVIGATE
**Source**: WebArena-Verified task 102
**Round**: 1 (Round 0 pilot 1 trial: baseline=29 step, KG=15 step. Round 1에서 3 trial 안정성 확보)

## Intent
> Navigate to the page showing the list of open issues in the a11yproject/a11yproject.com repository that have labels related to help wanted

Start URL: `http://localhost:8023`

## Hypothesis
Task는 (1) cross-project 이동, (2) issue list 진입, (3) 라벨 필터 적용의 3-hop 구조다. KG는 두 가지 *방향*만 노출한다.

1. **Path 단축**: `project/issue_list` 클래스가 `/{namespace}/{project}/-/issues` 경로를 가진다는 정보. agent는 task에서 namespace/project 값을 추출해 placeholder를 채우고 `goto`.
2. **Filter category 존재**: 해당 페이지에 "Label" 카테고리의 필터 컨트롤이 있다는 사실. category 이름과 어떤 컨트롤(드롭다운 vs 입력)인지까지만 노출.

KG는 **구체적 라벨 값(`help wanted`)이나 URL 쿼리 파라미터 값을 박지 않는다**. agent는 KG가 가리킨 라벨 dropdown을 직접 클릭·입력해 task의 "help wanted" 라벨명을 매칭. 이 분리가 KG의 step 단축이 *KG의 정보 우월*에서 오는지 *KG가 정답을 흘려서*인지 분리한다.

## Predicted baseline
- step 1: explore에서 a11yproject 검색 또는 dashboard에서 직접 클릭.
- step 2: 프로젝트 메인 → Issues 메뉴.
- step 3~4: 페이지 탐색·dropdown 발견 → 라벨 dropdown 식별.
- step 5: 라벨 dropdown 클릭·입력 → "help wanted" 적용.
- step 6: state=open 확인 → report_success.
- 예상 step 수: 6~8

## Predicted KG
- step 1: KG 힌트가 `/a11yproject/a11yproject.com/-/issues` path 단축을 노출. agent는 namespace/project를 task에서 추출해 직접 `goto`.
- step 2: 도달 페이지에서 KG가 사전 노출한 "Label filter category 존재" 정보로 *dropdown 발견 단계 생략*. 라벨 dropdown 직접 클릭.
- step 3: "help wanted" 입력·적용 (baseline와 동일한 page-surface 액션).
- step 4: report_success.
- 예상 step 수: 3~5 (baseline 대비 1~3 step 단축)

## Mechanism invocation signal (KG log)
- `[KG] inferred target=project/issue_list` (또는 동등)
- agent thought 또는 `goto` 호출에 `/{namespace}/{project}/-/issues` 경로 (쿼리 없이) 등장
- agent thought에 KG가 노출한 filter category 라벨 ("Label" 또는 동등) 인용
- 라벨 *값* `help wanted`의 출처는 agent의 task 해석 + page UI 상호작용 (KG가 노출한 게 아님을 KG hint payload snapshot으로 확인)

## Falsification criterion
- KG이 KG 힌트에서 `?label_name[]=help+wanted` 등 *값이 박힌 URL*을 받음 (= KG 힌트 모드가 design principle을 위반 → KG_MODE 자체 재검토)
- KG step 수 ≥ baseline step 수 (= path 단축 + filter category 인지가 본질적 단축을 만들지 못함 → H2 가설 refuted)

→ 두 번째 조건이 성립하면 H2는 본 task에서 refuted (메커니즘 모델 수정 필요).

## Notes
- 본 task는 design principle "KG는 방향, agent는 값"의 가장 직접적 검증. KG 힌트 모드가 URL 쿼리 값 노출을 suppress하는 동작이 본 가설의 *전제*.
- prior OpenAI 측정에서 archive(Batch B)에 baseline=11 step, KG=3 step 관측 — Claude KG 힌트 모드에서 동일 정도의 단축이 나오는지가 본측정의 핵심.
- KG 힌트 모드 구현(`hint_generator.py`의 `_minimal_mode()`)이 filter category section을 노출하는지, 라벨 값을 흘리지 않는지를 phase 0 smoke 1회로 hint payload 직접 inspection.
