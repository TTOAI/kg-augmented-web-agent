# L1: task 411 — 미매핑 클래스 능동적 오도 (MUT)

**Type**: MUTATE
**Source**: WebArena-Verified task 411

## Intent
> Change the LICENSE for repo byteblaze/cloud-to-butt to an MIT license

Start URL: `http://localhost:8023`

## Hypothesis
GitLab의 LICENSE 편집 페이지(파일 단위 편집 흐름)는 KG에 매핑되어 있지 *않다*. KG의 타겟 클래스 추론기는 후보 집합 강제 추론 구조라서 미매핑 페이지를 인지하지 못하고 차선 후보(예: `project/settings_general`)를 confident하게 선택. V1은 그 잘못된 target을 신뢰하고 settings 페이지를 반복 탐색하다 timeout. V0는 KG 안내 없이 repo 파일 트리·README 편집 흐름을 자유 탐색하므로 LICENSE 파일 편집까지 도달 가능 (단, network evaluator strict-match는 별개 이슈로 fail 가능).

## Predicted V0
- step 1~3: 프로젝트 도달 → 파일 트리 / Add LICENSE 링크 탐색.
- step 4~8: LICENSE 편집 페이지 도달 → 템플릿 선택 → MIT 적용 → commit.
- 예상 step 수: 8~12 (network evaluator 통과는 별개 변수)

## Predicted V1
- step 1: KG 추론기가 `project/settings_general`(또는 유사) 잘못 추론, 합의 K/K도 가능.
- step 2~N: 에이전트가 settings 페이지 진입 후 LICENSE 옵션 검색, 발견 실패 → 재시도 반복.
- step 60+ 또는 wall-clock 20분 timeout.
- 예상 step 수: timeout (∞)

## Predicted V1−tc
- step 1: 타겟 클래스 안내 없음. 에이전트는 page-surface 액션 (Add LICENSE 링크 등)만 보고 V0와 유사 경로로 자유 탐색.
- step 4~10: V0와 동등한 방식으로 LICENSE 편집 페이지 도달.
- 예상 step 수: V0와 유사 (8~14). timeout 회피.

## Mechanism invocation signal (V1 log)
- `[KG] inferred target=<settings 또는 file 관련 클래스>` (정확한 클래스명은 V1 첫 trial에서 확정)
- agent thought에 KG가 노출한 settings 메뉴 항목 반복 클릭 흔적
- 동일 페이지·메뉴 ≥3회 재방문 흔적

## Falsification criterion
- KG 추론기가 LICENSE 편집을 *정확히* 추론 (= KG가 매핑되어 있음 → task pick 자체가 L1 archetype 부적합)
- V1이 V0와 동등 또는 더 적은 step에 도달

→ 두 조건 중 *하나라도* 성립하면 refuted (이 task는 L1이 아님).
