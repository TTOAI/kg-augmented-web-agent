# Null2: task 664 — 텍스트 콘텐츠 중심 issue 작성 (MUT)

**Type**: MUTATE
**Source**: WebArena-Verified task 664
**Round**: 2 (Round 1의 Null1/44가 NAV에서 baseline=KG parity 확인. Null2는 MUT task type에서 동일 active control 작동 검증 — KG가 form 도달은 단축할 수 있으나 텍스트 콘텐츠 생성은 KG-orthogonal)

## Intent
> Open an issue with title "Question on future usage of Python 3.11" to ask the team's plans on adding Python 3.11 related resources in the respository awesome-python.

Start URL: `http://localhost:8023`

## Hypothesis
Task의 노력 분포는 (a) `awesome-python` 프로젝트의 issue_new_form 도달 ≈ 2~3 step, (b) title + description 자유 텍스트 입력 ≈ 1~2 step, (c) submit 1 step. KG는 (a)에 short-cut을 줄 수 있지만 (b)는 자유 텍스트 생성이라 KG 정보 없음. (a)의 단축 효과가 1~2 step이라 baseline와 KG의 *총* step 차이는 본질적이지 않으며, KG가 추가로 의미 있는 path를 줄 곳이 없다.

## Predicted baseline
- step 1: dashboard에서 awesome-python 직접 클릭 (또는 explore 검색).
- step 2: 프로젝트 → Issues 메뉴.
- step 3: New issue 버튼 클릭 → 폼 페이지.
- step 4: title 입력.
- step 5: description 입력.
- step 6: submit → report_success.
- 예상 step 수: 5~7

## Predicted KG
- step 1: KG 힌트가 issue_new_form URL 단축 노출 (`/{namespace}/{project}/-/issues/new`). 에이전트는 직접 `goto`.
- step 2: title 입력.
- step 3: description 입력.
- step 4: submit → report_success.
- 예상 step 수: 4~6

KG−baseline = 1~2 step 정도의 미미한 단축. **본질적 효과는 아님 — null로 분류.**

## Mechanism invocation signal (KG log)
- `[KG] inferred target=project/issue_new_form` (또는 동등)
- agent thought에 `/-/issues/new` URL 인용 또는 직접 `goto`
- title/description 입력 step에서는 KG 힌트 추가 발동 *없음*

## Falsification criterion
- KG step 수가 baseline보다 *3 이상 적음* (= KG가 텍스트 입력 단계에서도 본질적 단축을 제공)
- KG이 baseline보다 step이 *많음* (= KG가 방해)

→ 둘 중 하나라도 성립하면 refuted (Null2 archetype 부적합).

## Notes
- 본 cell의 단축 1~2 step은 H1/H2의 단축과 *질적으로 다른* 종류 (단순 URL goto). 결론 라벨: "KG는 URL 진입 단축에 한정, 텍스트 콘텐츠 생성에는 무관."
- 만약 Claude가 텍스트 입력에서 instable해서 step이 크게 늘어나면 (예: 폼 토글 누락 후 재시도), 그 패턴은 KG와 무관한 모델 행동이며 Null 분류는 유지.
