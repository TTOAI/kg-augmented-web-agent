지난 주차까지는 벤치마크 환경 구축과 웹에이전트의 기본 실행 구조를 마련하는 데 집중했다. WebArena-Verified 벤치마크 위에서 에이전트가 실제로 동작하는 것을 확인했고, 사전 지식 온톨로지를 설계한 뒤 이를 PoC으로 연결하는 것이 다음 목표였다. 이번 주에는 원래 사전 지식(Prior) 컴포넌트를 설계하고 baseline과의 비교를 통해 Prior의 필요성과 효과를 입증하려 했으나, 실험을 진행하는 과정에서 baseline 에이전트의 일반 추론 능력 자체를 먼저 충분히 끌어올려야 Prior의 효과를 정확히 측정할 수 있다고 판단했다. 이에 따라 이번 주차에서는 baseline 에이전트의 관측·실행·계획 레이어를 개선하고, WebArena-Verified 벤치마크의 사이트들 중 GitLab 사이트 대상 13개 task에 대해 반복 실험을 수행하면서 성능 변화를 측정하는 데 집중했다.

Prior를 먼저 도입하지 않고 baseline 개선을 우선한 이유는 다음과 같다. Prior를 섣불리 도입하면 에이전트가 특정 task에 실패했을 때 그 원인이 baseline의 일반 추론 능력 부족인지, Prior 설계의 정밀도가 부족한 것인지 판단하기 어렵다. 이 판단이 모호하면 Prior가 실제로 도움이 되는지, 정말 필요한 것인지를 입증하기도 어려워진다. 따라서 먼저 baseline의 성능을 최대한 끌어올리고, 더 이상 단순한 성능 향상으로는 풀지 못하는 문제가 명확해졌을 때 Prior 레이어를 도입하여 시험하는 것이 실험의 타당성을 높이는 방향이라고 판단했다.

baseline 개선은 크게 관측, 실행, 계획의 세 축에서 이루어졌다. 관측 측면에서는 에이전트가 페이지에서 수집하는 정보의 품질을 높여 LLM이 더 정확한 판단을 내릴 수 있도록 했고, 실행 측면에서는 LLM이 결정한 액션을 브라우저에서 수행할 때 발생하는 매칭 실패와 이벤트 처리 문제를 해결했다. 계획 측면에서는 실행 전에 task를 여러 하위 목표로 분해하는 Planning 레이어를 새로 도입하여, 에이전트가 중간 목표를 달성하지 않은 채 task 완료를 성급하게 선언하는 문제를 방지했다.

실험은 GitLab 사이트 대상 13개 task에 대해 진행했다. task 유형은 페이지 이동, 데이터 추출, 상태 변경으로 나뉘며, 각 유형별로 다양한 난이도의 task를 포함했다. 초기 baseline에서는 단순한 페이지 이동 task조차 성공률이 30%에 불과했으나, 관측·실행 레이어 개선 후 100%로 안정화되었다. 이후 드롭다운 상호작용, 동명 링크 구분, 필터 UI 클릭 기반 상호작용, 데이터 추출 정밀도, 프로젝트 검색 및 숨겨진 데이터 추출, 다단계 탐색을 통한 정보 수집 등을 순차적으로 해결하여 최종적으로 13개 중 10개 task에서 평가를 통과했다. 실험 과정에서 실패한 3개 task 중 하나는 사이트 특화 URL 파라미터가 필요한 경우로, baseline의 일반 추론만으로는 도달할 수 없는 Prior 영역의 문제로 분류했다. 나머지 두 개는 벤치마크 데이터의 해석 문제와 사이트 특화 지식이 동시에 필요한 경우로 분류했다.

실험을 진행하며 baseline의 한계와 Prior의 영역을 구분하는 기준도 점차 명확해졌다. 필터 드롭다운 탐색, Git Clone 버튼 클릭, Contributors 페이지 이동, 프로젝트 검색 같은 일반적인 UI 상호작용 패턴은 관측·실행 레이어의 개선과 Planning으로 해결할 수 있었다. 반면 특정 URL query parameter의 의미(visibility_level=20 = public), git commit author의 식별자 형식, 즉 "username"이 의미하는 것이 무엇인지(email), 특정 프로젝트의 존재 여부와 위치 같은 정보는 사이트에 대한 사전 지식 없이는 추론이 불가능하거나 굉장히 복합한 로직을 동반해야 했다. 다만 현재까지의 실험은 GitLab 한 사이트에 한정되어 있어, 구현한 개선 사항이 다른 사이트에서도 범용적으로 작동하는지는 아직 검증되지 않았다. 특히 특정 몇몇 로직은 GitLab의 UI 패턴에 맞춰 구현된 측면이 있어, 다른 사이트에서는 과적합 위험이 존재한다. 향후에는 GitLab 외 다른 벤치마크 사이트에 대해서도 실험을 확장하면서 일반 성능 향상과 사이트 과적합 사이의 균형을 조절해야 한다.

다음 주에는 먼저 현재 baseline의 안정성을 재측정한 뒤, Prior 컴포넌트 설계와 구현에 착수할 계획이다. 이미 Prior가 필요하다고 분류된 task를 첫 번째 대상으로 삼아, runtime layer에 설계되어 있는 사전 지식 구조를 활용하여 사이트별 사전 지식을 주입하고 그 효과를 측정할 것이다. 또한 GitLab 외의 벤치마크 사이트에 대해서도 동일한 baseline을 적용하여 범용성을 검증하고, 사이트별로 Prior가 필요한 지점과 baseline만으로 충분한 지점을 구분하는 실험을 설계할 예정이다.
