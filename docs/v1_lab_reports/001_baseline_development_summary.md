## 단계별 핵심 변경

### Phase 1~2: 기본기 확립

| 문제 | 해결 |
|---|---|
| 완료(done) 액션이 없어서 태스크 종료 불가 | done 액션 추가 |
| 아이콘만 있는 링크 클릭 실패 | 역할(role) 기반 요소 매칭으로 전환 |
| 페이지 상태 수집이 느림 | 병렬 수집으로 개선 |
| 액션 실행 후 결과를 LLM에 안 알려줌 | 성공/실패 피드백 전달 |

**결과**: Task 44 성공률 30% → 100%

## 핵심 인사이트

1. **태스크별 특수 로직은 과적합이다**: 한 태스크를 고치면 다른 태스크가 깨진다 (입력→클릭 자동 전환, 자동 Enter 등)
2. **Executor가 LLM 대신 판단하면 안 된다**: LLM의 결정을 덮어쓰는 로직이 예측 불가능한 부작용을 유발
3. **관측의 질이 LLM 판단의 질을 결정한다**: 보이는 요소만 필터링, 드롭다운 분리, 읽기전용 값 관측 등이 직접적으로 성공률 향상
4. **Planning이 성급한 완료 선언을 방지한다**: 단계별 목표 분해 없이는 LLM이 준비 단계에서 바로 완료를 선언

이 인사이트들이 003의 과적합 제거와 v2 아키텍처 설계, 004의 v3 전면 개선으로 이어짐.
